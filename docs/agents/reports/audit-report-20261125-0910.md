# Windows Quick Translate from a text selection

Checked commit `32b3916d` on 2026-11-25. The reported scenario starts with text selected in the Chrome address bar and the Viezan translation panel closed.

## Findings

The Qt panel receives the selection and creates a translation session. When the panel is hidden, its `snapshot` contains empty session and task lists. The activation handler evaluates `canSubmit` against that snapshot before it calls `show()`. The panel then displays the selected text and enables **Translate**, but the handler has already skipped submission. See [DesktopPanels.qml](../../../apps/desktop-qt/qml/DesktopPanels.qml).

## Verification

A local Qt 6.12 offscreen probe emitted the desktop integration’s `activated` signal with the same short Vietnamese phrase in each case. It used the packaged panel, a real workbench bridge with temporary state, and the existing Quick Panels fixture with an available model. It counted tasks created without contacting a translation provider.

| Panel before the shortcut | Selected text reached the draft | Translation requests created | Requests with submission checked after showing the panel |
| --- | --- | ---: | ---: |
| Hidden on first use | Yes | 0 | 1 |
| Already visible | Yes | 1 | 1 |
| Hidden after dismissal | Yes | 0 | 1 |

The last column used a temporary copy of the QML. The application source was unchanged by this investigation. With the current build, clicking **Translate** or pressing **Ctrl+Enter** in the populated draft invokes submission.

The Windows Qt job passed on this commit. Its Quick Panels test first opens with an over-limit selection and later submits a short draft explicitly. Its replacement action uses a test double. These cases leave automatic submission from a hidden panel and native Chrome selection capture untested. The focused local run passed all eight cases under the repository’s Fusion style. The first run used the macOS default Qt style and failed the six panel rows on customization warnings. [Windows CI job](https://github.com/trunghieupham59/viezan/actions/runs/45465849064/job/138700416547) · [Quick Panels test](../../../apps/desktop-qt/tests/WorkbenchBridgeTests.cpp)

## Initial diagnosis

On the original revision, the hidden Qt panel skipped automatic translation on first use and after dismissal. The temporary change produced exactly one request for each new session.

The probe began after native capture. On Windows, capture needs a focused external element exposing a selected UI Automation text range. Replacement also needs an editable value whose full contents and selection still match at write time. [WindowsSelection.cpp](../../../apps/desktop-qt/WindowsSelection.cpp)

## Fix and regression tests

The Qt activation handler now shows the panel after setting up the new session and its language pair, then checks `canSubmit`. The two `quickTranslateSubmitsFromHiddenPanel` cases exercise the desktop integration signal with an initially hidden panel and with a panel closed after a previous selection. Both failed against the original handler with zero requests. Both passed after the change, checking for one new task with the selected text, the configured target language and the new panel session ID.

The Qt 6.12 Release build passed on macOS. All nine CTest groups passed with writable Qt test profiles. The offscreen run skipped one accelerated Glass rendering case because it had no initialized graphics backend. The shared resource and documentation checks, 11 Node tests and 19 packaging tests under Python 3.13 passed.

## Windows focus and automatic replacement

The first patch left the workbench in front of Chrome and required clicking Paste. The Windows handler showed the shared editor window, requested activation and focused its draft. On macOS, Quick Translate presents a nonactivating card and attempts a verified replacement as soon as the translation finishes.

The Windows shortcut now presents an unowned, frameless Qt tool window near the pointer. The card submits the translation and requests replacement only for its current, visible session. The UI Automation write checks the original foreground window, focused element, value and selection. Closing the card discards pending automatic replacement. Open in Translate explicitly activates the workbench.

On macOS, the Qt Release build and all nine CTest groups passed. The focused run passed the first-open and reopen rows, the six language and appearance rows, and the selection-edit checks. The new assertions cover presentation flags, the hidden editor, single submission, automatic replacement, positioning and dismissal before a response. The offscreen suite skipped the accelerated Glass test. This change used the native UX and UI UX Pro Max focus guidance alongside the implementation and documentation workflows above.
