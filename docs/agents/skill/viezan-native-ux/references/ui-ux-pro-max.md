# UI UX Pro Max for Viezan

Use this reference for native design decisions and UX review. It supplements
the current Viezan design system; pure service/backend changes do not need it.

- Read the [installed skill](../../../../../.agents/skills/ui-ux-pro-max/SKILL.md).

  does not require npm packages, a global install or network access.
- The [upstream record](../../../../../.agents/skills/ui-ux-pro-max/UPSTREAM.json)

- The source precedence in `.claude/rules/ui-ux.md` still applies. Read current
  `docs/design/direction.md`, foundations, tokens and the affected screen spec

  `--persist` or create another `design-system/MASTER.md` for Viezan. Existing
  product direction also takes precedence over upstream's new-page generator.

## Search from the repository root

Read upstream's query contract, then choose only searches relevant to the task.
These are examples, not a mandatory batch for every edit:

```sh
# Material direction: verify that the match is liquid-glass, not glassmorphism.
python3 -B .agents/skills/ui-ux-pro-max/scripts/search.py "Liquid Glass" --domain style -n 1

# macOS: use explicit SwiftUI guidance, then check macOS applicability.
python3 -B .agents/skills/ui-ux-pro-max/scripts/search.py "keyboard focus" --stack swiftui

# Shared UX, including Qt: map the outcome to native controls.
python3 -B .agents/skills/ui-ux-pro-max/scripts/search.py "keyboard focus modal" --domain ux
```

From another directory, pass the absolute path to this checkout's `search.py`.
Python 3 is the only runtime dependency; `-B` avoids generated bytecode in the
vendored tree. The path above replaces upstream's Claude-plugin installation
path in this checkout.

Inspect the result identity, platform, applicability and linked official docs.
Retry once with a narrower query if the result is empty or off-topic. If it
still does not fit, say so and use current platform docs and Viezan rules.
Never claim a matching Qt stack: the pinned upstream has none. A `Web` row
may suggest a useful outcome, but its CSS/ARIA example is not native code.

## Native adaptation

| Concern | Apply in Viezan |
| --- | --- |
| Typography, spacing and controls | Use generated semantic tokens, system fonts and existing desktop control metrics. Do not import 16px body, 44px touch targets, Google Fonts or marketing layouts as desktop defaults. |
| macOS Liquid Glass | Use standard system controls and supported SwiftUI/AppKit material APIs. Follow current shell/component ownership and OS availability; keep the existing fallback for older macOS. |
| SwiftUI focus | Treat `@FocusState` as guidance where it fits. Preserve AppKit first-responder bridges, marked-text/IME handling, native menus and the existing keyboard-focus contract. |
| Qt Quick/QML | Use Qt Quick Controls and native accessibility/focus semantics. Map shared tokens to Qt components. `MultiEffect` and custom shaders may approximate glass within the QML scene; they do not provide Apple's system material or automatically blur the desktop behind a window. |
| Glass placement | Follow the current direction for shell/navigation/controls. Keep reading, composing and history surfaces stable and opaque. Do not spread glass to content because a style preset suggests it. |
| Accessibility and motion | Preserve visible keyboard focus, meaningful disabled/selected states, Reduce Transparency, Increase Contrast and Reduce Motion behavior where supported; provide appropriate fallbacks. |
| Performance | Bound blur area and animation work. Measure real target-platform rendering; do not infer cheap effects from catalog ratings or treat a macOS preview as Windows/Linux evidence. |

Use primary documentation for API details and check the installed SDK/Qt version:

- [Apple materials guidance](https://developer.apple.com/design/human-interface-guidelines/materials)
- [SwiftUI Liquid Glass](https://developer.apple.com/documentation/swiftui/applying-liquid-glass-to-custom-views)
- [AppKit NSGlassEffectView](https://developer.apple.com/documentation/appkit/nsglasseffectview)
- [Qt MultiEffect](https://doc.qt.io/qt-6/qml-qtquick-effects-multieffect.html)
- [Qt ShaderEffectSource](https://doc.qt.io/qt-6/qml-qtquick-shadereffectsource.html)

## Evidence

For a substantive design decision, record the query/domain or stack, relevant
matched row, what was adopted or rejected, and the native mapping in the task's
existing report. Do not save raw catalogs or invent a separate approval gate.
When the UI changes, run the relevant checks in `.claude/rules/ui-ux.md` and
`docs/migration/acceptance.md`, including actual keyboard/IME/screen-reader use.
Keep source, tests, builds and live acceptance separate; research is not a pass.

For skill updates, run `npm run check:agent`, `npm run check:docs`, the applicable
example searches above and the upstream data validator:

```sh
python3 -B .agents/skills/ui-ux-pro-max/scripts/validate_data.py
```
